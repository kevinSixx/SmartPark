# 07. Auditoría Frontend

La raíz React/Vite es `frontend/`: su `package.json` contiene `dev`, `build`, `lint` y `preview`. El `package.json` de raíz solo declara `lucide-react` y `react-router-dom`; explica `node_modules/` y `package-lock.json` de raíz como instalación separada, pero no constituye el proyecto Vite ni está referenciado por scripts. Confirmar con historial antes de quitarlo. `frontend/src/main.jsx` monta `BrowserRouter`; `App.jsx` define las páginas ADMIN (dashboard, usuarios, cara, vehículos, permisos, historial, auditoría de barrera, prueba acceso, personal) y GUARD (barrera, historial). Componentes `RequireRole`, `Layout`, `Sidebar`, `Header`, `TableFilters` y `useApi` coordinan UI.

`src/api/smartpark.js` centraliza Backend; `VITE_API_URL` vacío por defecto hace llamadas relativas al origen del Frontend. En Amplify independiente eso apunta a Amplify, salvo URL de API configurada o proxy. `src/api/edge.js` usa `VITE_EDGE_URL` o `http://127.0.0.1:9000`, y stream `/video`; GuardGate consulta `/health` y `/status`. `frontend/.env` existe con cuatro claves `VITE_*` (valores omitidos) y está **sin ignorar** por su `.gitignore`; revisar si las URL son públicas y no incluir secretos. `VITE_DEMO_AUTH` no tiene referencia localizada en `frontend/src/` y puede ser configuración antigua; confirmar historial/build antes de quitar. JWT se guarda en `localStorage` como `smartpark_session`; `request(...,{auth:true})` envía Bearer y borra sesión ante 401. El token persistente está expuesto a XSS; evaluar CSP y gestión de sesión.

## Contrato HTTP vs Backend

Las rutas principales del helper coinciden con decoradores y la instantánea OpenAPI: `/auth/login`, `/auth/me`, `/staff`, `/users`, `/vehicles`, `/permissions`, `/access-events`, `/access/process`, `/gates/{gate_id}/open|close|actions`, `/face-profiles/enroll` y `/{user_id}`. `enrollFace` usa `user_id` más `images`, correcto; `processAccess` usa `face_image`, `plate_image`, `event_type`, correcto. `frontend/tests/openapi-contract.test.js` comprueba parte de este contrato. **Desajustes operativos:** el helper usa Bearer solo en staff/gates/me, acorde al código actual, pero las demás rutas carecen de control JWT de servidor; la protección ADMIN en React no sustituye autorización Backend. `Dashboard.jsx` muestra «FastAPI 1.6» mientras Backend declara 1.7.2. La URL de API relativa por defecto no sirve automáticamente en Amplify. El puerto Vite puede pasar a 5174; ambos orígenes están en CORS Backend/Edge.

`frontend/dist/` es build local ignorado; `smartpark-amplify/` y cuatro ZIP son artefactos de despliegue, no fuente canónica. Hay cambios de trabajo previos en múltiples páginas, API, CSS y pruebas nuevas; esta auditoría no los alteró. No se ejecutó `npm run build`, `lint` ni tests para respetar la etapa de solo inspección. Falta un `.env.example` Frontend verificable y un procedimiento de build Amplify con variables.
